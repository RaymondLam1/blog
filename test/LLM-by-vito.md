2.1 Embedding嵌入
Embedding嵌入是一个较快较低成本使用模型的方式。一般称之为嵌入。embedding 一般是指将一个内容实体映射为低维向量，从而可以获得内容之间的相似度。OpenAI 的 embedding 是计算文本与维度的相关性，默认的 ada-002 模型会将文本解析为 1536 个维度。用户可以通过文本之间的 embedding 计算相似度。

2.1.1 简单原理
模型嵌入是通过模型将输入描述为向量。两个向量之间的距离衡量它们的相关性。小距离表示高相关性，大距离表示低相关性。

可以根据用户提供的语料片段与 prompt 内容计算相关度，然后将最相关的语料片段作为上下文放到 prompt 中，以提高 completion 的准确率。

2.1.2 场景
 embedding嵌入通常用于下面的场景：

搜索（其中结果按与查询字符串的相关性排名）

聚类分析（其中文本字符串按相似性分组）

建议（建议使用具有相关文本字符串的项目）

异常检测（识别相关性不大的异常值）

多样性测量（分析相似性分布）

分类（其中文本字符串按其最相似的标签分类） 以智能问答为例，进行讨论流程。

2.1.3 智能问答
针对当前比较火的问答型ai，可以基于现有模型做嵌入。文档问答设计采用”先检索再整合“的方案，整理流程如下。

首先从使用者视角分为两个大的步骤，数据索引和问答搜索：

数据索引

首先准备好文档，并整理为纯文本的格式。把每个文档切成若干个小的文本段

调用文本转向量的接口，将每个文本段转为一个向量，并存入向量数据库

文本转向量可以使用openai embedding 接口，也可以使用其他方案或自有模型，如fasttext/simbert

问答搜索

当用户发来一个问题的时候，将问题同样转为向量，并检索向量数据库，得到相关性最高的一个或几个文本段

将问题和文本段合并重写为一个合适的prompt发给openai api，返回结果；



请求时 prompt 构建大致如下：

从下面给出的信息来回答问题：“如何使用xx功能”
​
* 段落1: 您可以按照以下步骤使用xx功能......
* 段落2: xx功能是......
* 段落3: xx功能在......
从上面过程来看，最后一步其实是提供了相关的知识和问题，让模型进行概括。 简单来说，就是编写 prompt，让回答看起来更加拟人化。

2.1.3.1 思考
让我们抽象一下。按先检索再整合的步骤。

检索，将待检索和检索数据全部文本向量化，计算向量距离判断相关度，获取相关度TopN文本

整合，编写 prompt 让模型根据TopN文本和问题进行概括整合提炼

回到问答场景，来思考几个问题

检索使用相关度的好处对比普通分词搜索是什么？

这两个步骤的模型是否可以分别使用不同模型？

这两个步骤哪个比较重要？稍微不重要的步骤是否可以替换为效果稍差的模型

检索中使用通用模型对文本进行向量化，如果替换为其他通用模型，对检索的准确度有没有影响？

检索中模型替换为对某个领域知识的微调模型，对某个领域文本相关度是否有提升？

如果匹配的文本段已经是相关性良好且完整的信息段，那么编写 prompt 让模型整合的意义在于什么？

在检索结果不变的情况下，如何在整合阶段对对话中的用户输入进行反馈变更的？

总之，Embedding嵌入是一个较快较低成本使用模型的方式，对于模型的用的怎么样只在于脑洞是否足够大。

2.2 Finetune微调
相比大语言基础模型训练动则几十亿上万亿参数以及成吨的A100作为基础，微调所需的资源就非常少了。而且技术更新迭代之后，部分项目可以使用单块消费级显卡如RTX3060进行微调训练。因此微调是个较为可行的在短时间内拥有自己模型的途径之一。

预训练模型从其预训练数据集可以看出是个什么样的模型。通常是一个通用模型。当通用模型去做专业领域的推理的时候，由于缺少数据集的训练，往往不能得到比较专业结果。因此， 一个比较好的方式就是在一些通用基础大语言模型上进行微调。 相对比通用模型，微调模型有以下好处：

比设计编写prompt有更好的效果

适用于小数据集

训练成本低，速度快

2.2.2 选择合适的基础大语言模型，作为基础模型。
通常我们现在选择一些开源的大语言模型。同时要注意授权是否可用于商用，如果只是研究探索，则可忽略。

首先评估对比模型效果。如使用BIG-bench Hard、 Knowledge Assessments、Reading Comprehension、Linguistic Tasks以及MMLU等，通常在模型的论文中都会有；

关注模型的预训练数据集，在大多数情况下，研究者重新使用了已经被用来训练其他大型语言模型的数据源，从训练的数据集和比例可以知道该模型的训练方向。

其次需要考虑中文友好。有些基础模型在进行跑预训练的时候，大量甚至完全使用其他语种的语料作为训练集。那么在这个基础上使用中文数据集只进行微调，对中文的支持效果就比较有限。但是也有方式缓解（仅仅缓解），有个项目通过先扩充中文词表，再进行微调的方式也取得一些效果，但还是会受限于原模型的中文训练不充分的问题。

2.2.5 总结
未来AI的发展趋势还是不断向上，如果需要探索相关领域的能力边界，自有模型（起码微调模型）是未来必须的基础能力。从上面的训练过程可以看出，其实整个过程对于LLM本身的细节问题的处理几乎都没有，关键在于数据集的准备（大力出奇迹）和后期的评估调整（加大剂量）。因此微调这条路还是需要不断进行技术积累。对个人而言，能训练一个自己的模型也是非常有意思的事。

3. 探索方向
结合我个人对AI的理解做一些思考。给出一些技术方向上的储备建议。为现在或未来的产品提供技术储备。

3.1 组织内部数据集
虽然基座在于模型，但数据决定一切。未来模型巨大化使得不是每个中小型公司都能够训练大语言模型。模型的通用化使得谁掌握数据谁就能微调表现良好的AI模型。

3.1.1 高质量的脱敏数据
但为了保护数据安全，训练模型前需要将数据进行脱敏处理。模型需要足够多的高质量脱敏数据才能训练出较好表现的模型。

生成数据时，也要考虑数据的分布，数据的多样性，数据的质量等。

3.1.2 结构化的数据准备
对于lora的数据格式，我们一般使用 ”{ "instruction": "总结以下文章", "input": "[文章内容]", "output": "这篇文章主要讲了\n1.xxxx。\n2.xxxxx。\n" },“的方式进行训练。

为了得到规整的数据，需要对数据进行收集、过滤、清洗，储存。还包括生成数据的方法，工具，以及人工审核等。
